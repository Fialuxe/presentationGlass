# PC とスマホの間のメッセージ

PC 側の拡張とスマホのアプリは、WebSocket で JSON のメッセージをやり取りします。スマホが待ち受け、PC がつなぎに行きます。ポートは 8765 です。

PowerPoint など別のソフトに対応するときも、このメッセージを送れば、スマホとグラスの側は変えずに済みます。

メッセージの名前は、拡張では `chrome-extension/lib/protocol.js` に、Android アプリでは `Protocol.kt` に定義しています。名前を変えるときは、両方とこの文書をそろえて直します。

## バージョン

いまのバージョンは 2 です。メッセージの形を変えたら、バージョンを 1 つ上げます。スマホは、`hello` のバージョンが自分と違う接続を断ります。

## PC からスマホへ

| type | 中身 | 送る時 |
|---|---|---|
| `hello` | `version`: 通信のバージョン。`pin`: スマホに出ている 4 桁の PIN。`client`: 送り手の名前。 | つないだ直後に必ず送ります。認められるまで、スマホはほかのメッセージを無視します。 |
| `deck` | `title`: 資料名。`count`: スライドの枚数。 | つないだ直後と、スライドを読み直した時に送ります。 |
| `slide-image` | `index`: スライドの番号。`title`: スライドの最初の 1 行の文字。`mime`: 画像の形式。いまは `image/jpeg` だけです。`data`: 画像を base64 にしたもの。 | `deck` の後に、1 枚ずつ送ります。いまのスライドに近い順に送ります。 |
| `slide` | `index`: いまのスライドの番号。最初のスライドが 0 です。 | 番号が変わった時と、つなぎ直した時に送ります。 |
| `status` | `level`: `warn` か `ok`。`code`: 問題の種類。`message`: 発表者に見せる文。`detail`: 技術的な理由。拡張の記録にだけ出します。 | 問題が起きた時に `warn` を、直った時に同じ `code` で `ok` を送ります。 |
| `reset-timer` | なし | 経過時間を 0 に戻す時に送ります。 |
| `ping` | なし | 20 秒ごとに送ります。接続が生きているかを確かめるためです。 |

`status` の `code` には、次の 3 つがあります。

| code | 意味 |
|---|---|
| `deck-load-failed` | スライドを読み込めません。 |
| `slide-number-unreadable` | スライドショー中に、いまのスライド番号を読み取れません。 |
| `navigation-failed` | 「次へ」「前へ」を受けても、スライドを動かせません。 |

## スマホから PC へ

| type | 中身 | 送る時 |
|---|---|---|
| `welcome` | `version`: スマホの通信のバージョン。 | `hello` を認めた時に送ります。 |
| `error` | `message`: 理由。 | PIN かバージョンが合わない時に送り、接続を切ります。 |
| `navigate` | `action`: `next` か `prev`。 | グラスかスマホの画面で「次へ」「前へ」が押された時に送ります。 |
| `pong` | なし | `ping` への返事です。 |

`navigate` を送っても、スマホは自分で番号を進めません。PC がスライドを動かし、新しい番号を `slide` で送り返します。いまのスライドを決めるのは、いつも PC です。

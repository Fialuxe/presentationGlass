# PresentationGlass

Google スライドのいまのスライドを Meta Ray-Ban Display に表示し、聴衆を見ながら発表するためのツールです。

聴衆は、PC に HDMI でつないだ画面でスライドを見ます。発表者は、右目の画面でいまのスライドを見ます。スライドは、右手首の Neural Band で指を滑らせて進めます。Neural Band は、指の動きを読み取るリストバンドです。発表者は手元の PC を見なくてよいので、聴衆を見ながら話せます。

この README は、[standard-readme](https://github.com/RichardLitt/standard-readme) の章立てに沿っています。

## 背景

スライドを確かめようとすると、発表者は手元の PC か後ろのスクリーンに目を向けます。そのたびに、聴衆から目が離れます。Meta Ray-Ban Display は、右目のレンズに小さな画面を持つメガネです。この画面にスライドを出せば、発表者は顔を上げたまま話せます。

Meta は 2026 年 5 月に、外部のアプリからこの画面に表示できる開発者プレビューを公開しました。このツールは、その Wearables Device Access Toolkit を使います。

## インストール

### 必要なもの

| もの | 用途 |
|---|---|
| Meta Ray-Ban Display と Neural Band | スライドの表示と、スライドの操作に使います。 |
| Android スマホ（Android 12 以上） | PC とグラスの間を中継します。Meta AI アプリが入っている必要があります。 |
| PC と Chrome | Google スライドを開き、HDMI で聴衆の画面に映します。Bluetooth が必要です。 |
| JDK 17 以上と Android SDK 36 | Android アプリのビルドに使います。 |

### Android アプリ

スマホを USB でつなぎ、USB デバッグをオンにしてから、次を実行します。

```sh
cd android
./gradlew installDebug
```

Windows では `gradlew.bat installDebug` を使います。Android Studio で `android/` を開いて入れることもできます。

次に、Meta AI アプリで開発者モードをオンにします。「設定」→「アプリ情報」で、アプリのバージョンを 5 回タップします。開発者モードでは、Meta の開発者センターで発行する ID は要りません。配布するときは、`android/local.properties` に `mwdat_application_id` と `mwdat_client_token` を書きます。

### Chrome 拡張

1. Chrome で `chrome://extensions` を開き、「デベロッパー モード」をオンにします。
2. 「パッケージ化されていない拡張機能を読み込む」で、`chrome-extension/` フォルダを選びます。

拡張を更新したときは、同じ画面で拡張を読み込み直します。

## 使い方

### 準備

スマホのアプリの画面は、上から 4 つの手順に分かれています。

1. **グラスとアプリをつなぐ:** 「グラスを登録」を押します。最初の 1 回だけ必要です。
2. **PC の Bluetooth キーボードとして使う:** 初めての PC では、ペアリングが 1 回だけ必要です。「PC から見つけられるようにする」を押し、表示された確認を許可します。次に PC で「設定」→「Bluetooth とデバイス」→「デバイスの追加」→「Bluetooth」を選び、「PresentationGlass」を選びます。状態が「PC と接続中」になれば完了です。
3. **PC の Chrome 拡張をつなぐ:** スマホと PC を同じネットワークにつなぎます。テザリングでも Wi-Fi でも構いません。Chrome 拡張のアイコンを押し、スマホに出ている IP アドレス・ポート・PIN を入力します。
4. **グラスに表示する:** 「表示を始める」を押します。

最後に、PC で Google スライドを開き、スライドショーを始めます。

### Neural Band の操作

| 指の動き | 起きること |
|---|---|
| 親指を人差し指の上で右に滑らせる | 次のスライドに進みます。 |
| 親指を人差し指の上で左に滑らせる | 前のスライドに戻ります。 |
| つまむ | いまのスライドの動画を再生・一時停止します。 |

スマホが PC の Bluetooth キーボードとしてつながっているときは、左右の操作は本物の矢印キーとして PC に届きます。そのため、Google スライド以外のスライドのソフトでも動きます。つながっていないときは、Chrome 拡張が Google スライドを直接動かします。

### グラスの表示

表示の形は、スマホの「グラスに表示する」の欄で選べます。

| 形 | 表示 |
|---|---|
| パターン 1 | いまのスライドを上に、次のスライドを小さく下に表示します。 |
| パターン 2 | いまのスライドを、周りの余白を切り落としたうえで、できるだけ大きく表示します。次のスライドは、最初の行の文字だけを灰色で 1 行表示します。最後のスライドでは「次: なし（最後のスライド）」と出ます。 |

グラスの画面は、黒い部分が透けて見えます。白い背景のスライドは、色合いを保ったまま明るさを反転して表示します。白い背景がそのまま光ると、聴衆の上にまぶしい四角が重なるからです。

動画の再生中は、右上に緑の三角が出ます。PC との接続が切れたときや、PC がスライドを動かせないときは、下にだいだい色の警告が出ます。

グラスが手元にないときは、スマホの「グラスなしで試す」をオンにします。Meta の仮想グラスが動き、PC の Chrome でグラスの表示を確認できます。

### 言語

スマホのアプリと Chrome 拡張は、日本語・英語・中国語（簡体字）・韓国語・シンハラ語・マレー語・タミル語に対応しています。スマホのアプリはスマホの言語設定に、Chrome 拡張は Chrome の表示言語に合わせて切り替わります。どちらも、対応していない言語では英語で表示します。Android 13 以上では、「設定」→「アプリ」→ PresentationGlass →「言語」で、アプリだけ別の言語にできます。

## 仕組み

### 全体の流れ

データは「PC → スマホ → グラス」の順に流れます。

| 部分 | 場所 | 役割 |
|---|---|---|
| Chrome 拡張 | `chrome-extension/` | Google スライドから、いまのスライド番号とスライドの画像を取り出します。スマホからの指示で、スライドを動かし、動画を再生します。 |
| Android アプリ | `android/` | PC からの接続を待ち受けます。受け取った内容を、グラスに表示します。PC の Bluetooth キーボードとしても働きます。 |
| グラス | Meta Ray-Ban Display | スライドを表示し、Neural Band の操作を受け取ります。 |

いまのスライドを決めるのは、いつも PC です。グラスで次へ進む操作をすると、スマホがグラスの表示を先に変えます。同時に、PC に矢印キーか指示を送ります。PC がスライドを進め、新しい番号をスマホに送り返します。PC とスマホの間のメッセージは、[docs/protocol.md](docs/protocol.md) にまとめています。

### PC とスマホの通信

会場の Wi-Fi では、端末どうしの通信が止められていることがよくあります。そのときは、スマホのテザリングに PC をつなぎ、PC とスマホだけのネットワークを作ります。

スライドの画像は、接続した直後に 1 回だけ送ります。発表中に送るのは、スライド番号だけです。そのため、通信が遅くてもグラスの表示はすぐ変わります。

接続が切れると、拡張は 1 秒から 10 秒の間隔で自動的につなぎ直します。同じネットワークの他人がスライドを読めないように、接続には 4 桁の PIN が必要です。

### Bluetooth キーボード

スマホは、Android の Bluetooth HID デバイスの仕組みで、PC のキーボードとして働きます。PC には本物のキー入力が届くので、どのスライドのソフトでも矢印キーで動きます。

Chrome は、人がページを操作したあとでしか、音つきの動画を再生しません。拡張が出す命令は、人の操作として扱われません。一方、Bluetooth キーボードのキー入力は、人の操作として扱われます。

そこで、つまむ操作では、スマホから PC へ Pause キーを 1 回送ります。そのあとで、Chrome 拡張に動画の再生を頼みます。Pause キーは、スライドのソフトでは何も起こしません。

一度ペアリングした PC には、スマホのアプリを開いたときに自動でつなぎ直します。この処理は `android/app/src/main/java/com/presentationglass/app/HidController.kt` にあります。

### スライドの画像

拡張は、開いているスライド全体を PDF として 1 回だけダウンロードします。その PDF を、Mozilla の pdf.js で 1 ページずつ画像にします。pdf.js は `chrome-extension/vendor/pdfjs/` に入っており、Apache-2.0 ライセンスです。

Google は、短い間に何度もダウンロードすると `HTTP 429` を返して断ります。`HTTP 429` は、回数が多すぎるという拒否です。スライドを 1 枚ずつダウンロードすると、スライドが多いときにすぐ断られます。そのため、PDF は 1 回だけ受け取ります。

スライドショーを始めると、拡張はスライドを読み直します。この読み直しも、前の読み込みから 5 分以上たったときだけ行います。理由は、上と同じく `HTTP 429` を避けるためです。

画像は、いま表示しているスライドに近い順に送ります。そのため、全部の画像が届く前でも、グラスにはすぐいまのスライドが出ます。Google のアカウント連携の設定は要りません。

### Google スライドの操作

Google スライドには、再生中のスライドショーを外から動かす公式の API がありません。そのため拡張は、Google スライドの画面の部品を直接読み、直接クリックします。Google が画面を作り替えると、この部分は壊れるおそれがあります。

壊れたときに直す場所を 1 か所にするため、Google スライドに依存する処理は `chrome-extension/adapters/google-slides.js` にまとめています。画面の部品の名前は、このファイル冒頭の `SELECTORS` にあります。

いまのスライド番号は、次の順に読み取ります。1 つ目が使えなければ、次の方法を試します。

1. スライドショーで、Google が読み上げ用に付けている「スライド 1/2」という文字から読みます。
2. スライドショー下部のバーに出ている番号から読みます。
3. 編集画面で、URL のスライドの ID と、左側のスライド一覧から読みます。

拡張は、スライドを動かすたびに、スライド番号が変わったかを確かめます。番号が変わらないときは、グラスに「スライドを動かせません」と出します。発表者は、すぐ手元のリモコンに切り替えられます。

## 開発

### フォルダの構成

| 場所 | 中身 |
|---|---|
| `android/` | Android アプリです。Kotlin と Jetpack Compose で書いています。 |
| `chrome-extension/` | Chrome 拡張です。ビルドは要りません。 |
| `chrome-extension/adapters/` | スライドのサービスごとの処理です。いまは Google スライドだけです。 |
| `chrome-extension/lib/` | 拡張の各部で共有する処理です。メッセージの名前、画面の文言、PDF を画像にする処理があります。 |
| `chrome-extension/vendor/` | 外部のライブラリです。いまは pdf.js だけです。 |
| `docs/` | PC とスマホの間のメッセージの説明です。 |
| `tests/e2e/` | 拡張を本物の Google スライドで動かす試験です。 |

### 書き方の決まり

| 対象 | 決まり |
|---|---|
| メッセージの名前 | `kebab-case` の英語にします。定義は拡張の `lib/protocol.js` と、Android の `Protocol.kt` の 2 か所だけに置きます。 |
| 画面の文言 | コードの中に直接書きません。Android では `res/values*/strings.xml` に、Chrome 拡張では `lib/i18n.js` に置きます。 |
| コードのコメントと開発者向けのログ | 英語で書きます。発表者が読む文言は、上の文言ファイルを通して各言語で出します。 |
| JavaScript | 拡張の共有の名前は、`PresentationGlass` の下にまとめます。それ以外の名前は、各ファイルの中に閉じ込めます。 |
| 書式 | `.editorconfig` に従います。字下げは空白 2 個、1 行は 100 字までです。 |

Android のライブラリのバージョンは、Meta 公式の DisplayAccess サンプルにそろえています。Meta が試したバージョンで SDK を使うためです。新しい版を知らせる Lint の警告は、`android/app/lint.xml` で止めています。

### 言語を足す

| 対象 | 手順 |
|---|---|
| Android アプリ | `android/app/src/main/res/values/strings.xml` を `values-<言語コード>/strings.xml` に複製して訳します。基本の文言は英語です。Android 13 以上の言語設定の一覧は、このフォルダから自動で作られます。 |
| Chrome 拡張 | `chrome-extension/lib/i18n.js` の `MESSAGES` に、言語コードの項目を 1 つ足して訳します。訳していない文言は英語で出ます。Chrome 標準の `_locales` はシンハラ語に対応していないため、この形にしています。 |

### 確認の手順

Android アプリは、次でビルドと静的検査をします。

```sh
cd android
./gradlew assembleDebug lintDebug
```

拡張は、次の試験で確かめます。2 枚以上ある公開スライドの URL を渡します。

```sh
cd tests/e2e
npm install
npx playwright install chromium
node run.mjs <公開スライドの URL>
```

この試験は、スマホの代わりに、同じ受け答えをする試験用のサーバーを PC で動かします。Google の画面が変わった場合を試すために、下部バーのボタンの名前をわざと書き換える試験も含みます。Google が画面を変えていないかを確かめるため、発表の前にもこの試験を回すことをおすすめします。

### 試してやめたこと

Neural Band で PC のマウスを動かす操作は、試したうえでやめました。Neural Band からは、つまんだまま動かす入力が届きませんでした。また、すばやく 3 回つまむ操作は、3 回目が届かないことが多くありました。ただし、キーボードの設定（HID の記述子）にはマウスを残しています。記述子を変えると、すべての PC でペアリングをやり直す必要があるためです。
